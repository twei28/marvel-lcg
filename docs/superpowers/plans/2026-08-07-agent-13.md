# Pack Agent 13 — plan d'implémentation

> **Pour les agents :** SOUS-SKILL REQUISE : utiliser superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`).

**But :** livrer Agent 13 comme héros jouable de bout en bout, sur la tranche 79xxx.

**Architecture :** un pack de cartes suit toujours le même chemin dans ce projet. Les données décrivent les cartes (`data/cards.json`), un script Python par carte à capacité porte le comportement (`src/cards/pack/agent_13/`), un deck de départ les assemble, et quatre outils plus une partie réelle le prouvent. Aucune modification du moteur n'est nécessaire : les huit points d'accroche ont été vérifiés avant d'écrire la spec.

**Spec :** [`docs/superpowers/specs/2026-08-07-agent-13-design.md`](../specs/2026-08-07-agent-13-design.md)
**Textes des cartes :** [`docs/superpowers/specs/2026-08-07-agent-13-releve-cartes.md`](../specs/2026-08-07-agent-13-releve-cartes.md) — la seule source, relevée sur les 23 scans. Ne jamais écrire un texte de mémoire.

**Stack :** Python 3.10 (moteur), JSON (données), TypeScript (textes français du plateau).

## Contraintes globales

- Python **3.10 obligatoire** : `~/marvel-work/python/bin/python3.10`, à travers WSL.
- Travailler côté **Windows**, dans `Fusion/marvel-lcg-src/`, puis pousser vers `$HOME/marvel-work/fusion/marvel-lcg-src/` après chaque commit. C'est l'inverse de ce que dit le §5 du guide, et c'est délibéré : une session parallèle écrit dans la copie WSL.
- Le moteur exécute `.game/*.pyc`, pas `src/`. Reconstruire par `launcher_fast.py --build-only` après toute édition de `src/`, et coller la sortie brute. **Jamais `--clean`.**
- Cinq instances du jeu tournent, sur les ports 2345 et 2351 à 2354. **Ne jamais employer `pkill`.** Pour lancer un serveur, prendre un port libre avec une configuration temporaire, et l'arrêter par son PID.
- Toutes les valeurs de `desc` dans `cards.json` sont des **chaînes**, jamais des nombres.
- Un doute sur le sens d'une carte se pose à l'utilisateur en multichoix, une question par carte, comme l'exige le §4.1 du guide. Ne jamais trancher seul.
- Commits en français, sans em dash (—).
- Branche `pack-agent-13`. Ajouter les fichiers du pack à git, un par un et nommément : `src/cards/` n'est pas suivi, et un `git add` de dossier capturerait des milliers de fichiers hors périmètre.

```python
from . import *

# Secret Agent
# Hero Resource: Exhaust Secret Agent -> generate a wild resource.
# Montage repris de Web-Shooter (01008), sans son cout en compteur 'web'.

def GetAbilities() -> Sequence['Ability']:

    return [
        AbilityFactory.CanGenerateResources(
            AbilityType.HeroResource,
            Resources("G")
        ).SetCostFunc(CostFunc.Exhaust("This"))
    ]
```

C'est l'idiome à reproduire : un `GetAbilities()` qui rend une liste, des
facteurs `AbilityFactory`, et un commentaire de tête qui rappelle le texte
imprimé et nomme la carte prise pour modèle.

**Les cinq autres cartes de cette tâche ne sont pas données en code**, et c'est
délibéré : leur montage exact dépend de facteurs `AbilityFactory` qu'il faut

plus nuisible qu'utile. Le tableau ci-dessus dit ce que chaque carte doit faire
et où chercher ; le §3 du guide donne la grammaire complète.

**Convention de commentaire du projet.** Les cartes fan-made portent un
commentaire de tête qui explique POURQUOI le montage est celui-là, et notamment
les voies essayées qui ne marchent pas, avec leur date. Voir
`src/cards/pack/agent_anti_venom/agent_anti_venom/74006.py`, qui documente en

### Tâche 3 : les trois cartes qui comptent les icônes de bonus

C'est la mécanique du pack, et le défaut le plus probable : une carte qui rend

**Fichiers :**

- Créer : `.../agent_13/agent_13/79004.py` Infiltrate
- Créer : `.../agent_13/agent_13/79008.py` Agent 13's Pistol

**Interfaces :**
- Consomme : l'arborescence de la tâche 2.
- Produit : rien pour les autres tâches ; ces trois cartes sont indépendantes.

- [ ] **Étape 1 : lire le modèle officiel**

`src/cards/pack/scw/scarlet_witch/15004.py`, Hex Bolt. Il défausse des cartes
de rencontre, compte leurs icônes par `FacesCounter.CountTotalBoostIcons([face])`
et branche selon le résultat. C'est le vocabulaire exact des trois cartes.

- [ ] **Étape 2 : le Pistolet, `79008`, le plus proche du modèle**

Réponse après une attaque d'Agent 13 : épuiser le Pistolet, défausser la carte
du dessus du deck de rencontre par `Worlds.DiscardEncounterCards(1, effect)`,
compter ses icônes, infliger autant de dégâts à un ennemi.

Le libellé dit « for each boost icon discarded this way » : si la carte
défaussée n'a aucune icône, l'effet inflige zéro dégât, ce qui est un résultat
légitime et non une erreur.

- [ ] **Étape 3 : Infiltrate, `79004`**

Action héros de type manigance : retirer 3 menaces d'un complot, REGARDER la
carte du dessus du deck de rencontre sans la défausser, retirer 1 menace de plus
par icône, puis proposer au joueur de la défausser.

Deux points de vigilance : regarder n'est pas défausser, et la défausse finale
est optionnelle, donc un `MayChooseOneAbility` que le pilote de test décline par
défaut. La tâche 8 devra employer `accepter_choix: True` pour l'exercer.

- [ ] **Étape 4 : Sharon Carter, `79001b`**

Action une fois par round : choisir une carte dans la défausse de rencontre, la
remettre sur le dessus du deck, puis retirer d'un complot autant de menaces que
la carte porte d'icônes.

Pour la sélection dans la défausse, `Worlds.GetEncounterDiscardPileCards`. Pour
le déplacement, `MoveToTop` comme dans `src/game/operate/faces.py:69`.

Si la défausse de rencontre est vide, la capacité ne doit rien faire plutôt que
de lever une erreur. C'est le cas au premier tour d'une partie.

### Tâche 4 : la face héros et Parting Shots

- [ ] **Étape 1 : Agent 13, `79001a`**

Réponse après un pouvoir de base : réactiver Agent 13 et faire une attaque de
base contre un ennemi, une fois par round.

Le point d'accroche est `AbilityFactory.AfterUnitUseBasicPower`, dans
`src/game/ability/factory/friend.py:373`. Il accepte un paramètre `powers=`, qui
restreint aux pouvoirs voulus. Le texte dit « a basic hero power », donc les
trois pouvoirs de base du héros, pas ceux d'un allié : lire la signature du
facteur et employer `which_unit="You"`.

- [ ] **Étape 2 : Parting Shots, `79005`**

Interruption héros, avant qu'un ennemi initie une attaque contre vous :
2 dégâts à cet ennemi, l'attaque gagne « distance ». Puis, en option, basculer
en forme alter-ego, auquel cas cet ennemi manigance au lieu d'attaquer.

l'identité (`src/game/card/face/card_type/identity.py:77`). `ChangeForm`
n'existe pas, et un appel à un nom inexistant derrière un choix optionnel n'est
attrapé ni par `test_cards` ni par `test_capacites`.

La bascule est un choix du joueur, donc là encore un chemin que le pilote
décline par défaut.

- [ ] **Étape 3 : Hallucination, `79013`**

À la révélation : défausser des cartes du deck de rencontre jusqu'à en défausser
un sbire, révéler ce sbire et attacher cette carte dessus ; si c'est impossible,
la carte gagne « déferlante ». Puis, interruption forcée : quand le sbire
attaché subirait le moindre dégât, le défausser et poser 3 menaces sur la
manigance principale.

Défausser en boucle par `Worlds.DiscardEncounterCards`, attacher par `AttachTo2`
(`src/game/card/face/attribute/can_attach.py:49`).

Le cas « impossible » est réel : un deck de rencontre sans sbire s'épuiserait.
Prévoir la sortie de boucle plutôt que de tourner indéfiniment.

- [ ] **Étape 4 : Doctor Faustus, `79012`, la plus délicate**

Deux capacités. D'abord, il ne peut pas subir de dégâts tant que le joueur est
engagé avec un autre sbire : `message.PreventDamage("All", effect)`
(`src/game/message/sender/sender_damage.py:133`), sous condition.

Ensuite, l'interruption forcée : quand Doctor Faustus attaquerait le joueur
alors que celui-ci contrôle un allié, cet allié inflige au joueur des dégâts
égaux à sa propre valeur d'attaque, à la place.

**Aucune carte du dépôt ne retourne un allié contre son héros.** Si le montage
résiste, poser la question à l'utilisateur en multichoix plutôt que d'improviser,
comme l'exige le §4.1 du guide. Deux points à cerner : quel allié si le joueur
en contrôle plusieurs, et si l'allié subit lui-même quoi que ce soit.

- [ ] **Étape 5 : Sleeper Agent, `79015`, l'obligation**

L'obligation cible NOMMÉMENT l'allié Captain America, `79002`. La première
option ne doit être proposée que si cet allié est en jeu.

C'est la tâche qui décide si le pack est livré ou non. Les sept cartes

Sept cas, un par carte : `79001a`, `79001b`, `79004`, `79005`, `79008`,
`79012`, `79013`.

doit relever une valeur **non nulle**, sur une carte de rencontre dont on
connaît le nombre d'icônes. Un cas qui passerait au vert avec zéro icône ne
prouve rien : c'est exactement le défaut que cette tâche existe pour attraper.

employer la clé `accepter_choix: True`. Sans elle, le pilote décline le choix et
le chemin de code n'est jamais exercé, même si le cas est vert.
