# Plan 03-01 — Porte privée de la V2 mobile

## Objective

Activer automatiquement la future interface V2 uniquement pour le navigateur
qui entre comme hôte de la table du compte `arnaud`. Tous les autres comptes,
les invités et les spectateurs conservent la version actuelle.

## Context

- Le site connaît le compte, mais le moteur de jeu est un serveur séparé.
- Le site dépose l'hôte sur le moteur via `/claim_seat?...&to=prepare`.
- Le moteur sait vérifier que la clé présentée est bien celle du siège 0.
- La sélection V2 est une préférence d'affichage, jamais une autorisation.

## Tasks

1. Faire produire `to=prepare-v2` uniquement par `Partie.lien_hote()` lorsque
   le propriétaire normalisé de la table est `arnaud`.
2. Faire reconnaître cette destination par `/claim_seat`, puis poser un cookie
   de session `ui_version=v2` lisible par le frontend. Une entrée V1 efface ce
   cookie afin qu'un ancien essai ne contamine pas une autre session.
3. Couvrir les liens Arnaud, les autres comptes, les invités et les mauvaises
   clés par des tests de non-régression.

## Success Criteria

- Le lien hôte d'Arnaud porte `to=prepare-v2`.
- Le lien hôte d'un autre compte porte toujours `to=prepare`.
- Seul un `prepare-v2` valide sur le siège 0 pose `ui_version=v2`.
- Les liens d'invitation restent sur le salon actuel et ne posent pas la V2.
- Les tests du site et d'authentification restent verts.

## Suite du chantier

Les plans suivants construiront, derrière ce cookie, le socle de navigation
V2 puis les écrans mobiles par lots atomiques : préparation, galerie/decks,
replay, plateau et enfin audit multi-formats.
