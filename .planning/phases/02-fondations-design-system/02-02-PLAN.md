<objective>
Poser la chaine de build de la nouvelle UI : React 19 + TypeScript 6 + Vite 8, en multi-pages, configuree des le depart pour ne produire QUE ce que le serveur Python sait servir.

Purpose : c'est la moitie technique du critere 1 de la phase. Le piege a desamorcer tout de suite est le routage par extension du serveur : un `.png`, un `.woff2` ou un `.json` sortant du build renvoie 200 avec une image JPEG vide, sans la moindre erreur en console. Le garde-fou d'extensions transforme ce piege silencieux en echec de build lisible.
Output : le projet `ui-app/`, une page `vitrine.html` minimale qui monte du React, et `node outils/verifier-sortie.mjs` qui refuse tout intrus.

Ce plan ne touche a AUCUN fichier du jeu et ne pilote pas le serveur : il peut tourner en meme temps que le plan 02-01.
</objective>

**A. `ui-app/vite.config.ts`** : reprendre exactement la configuration validee par la recherche, commentaires en francais compris (ils expliquent des contraintes non evidentes) :
```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import checker from 'vite-plugin-checker'
import { resolve } from 'node:path'

export default defineConfig({
  // Adresse reellement servie par le serveur Python (verifie en direct).
  base: '/app/',

  plugins: [react(), checker({ typescript: true })],

  build: {
    outDir: 'dist',        // LOCAL. La recopie vers le jeu est faite par deployer.sh.
    // Le serveur n'a AUCUNE route pour .png / .webp / .woff2 / .json, et sa
    // route .svg ne lit que assets/textures/ a plat. On force donc l'inlining
    // de tout asset importe : rien d'autre que .html / .js / .css ne doit sortir.
    assetsInlineLimit: () => true,
    // .js.map renvoie 404 en mode RELEASE, pose par les deux launchers.
    sourcemap: false,
    // Vite 8 : rollupOptions a ete RENOMME rolldownOptions.
    rolldownOptions: {
      input: {
        vitrine: resolve(import.meta.dirname, 'vitrine.html'),
      },
    },
  },
})
```
