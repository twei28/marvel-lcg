<objective>
Ecrire le design system tokenise complet, lui donner un controle de contraste automatique, et faire consommer ces tokens par la premiere feuille ancienne.

Purpose : criteres 2, 3 et une moitie du critere 4. Le piege le plus couteux de la phase est ici : ajouter `tokens.css` ne change rien tant que les feuilles anciennes gardent leurs valeurs en dur, parce qu'une propriete personnalisee n'entre pas en concurrence avec `background-color: rgb(43,43,43)`. Le travail reel est une SUBSTITUTION.
Output : `tokens.css` complet et deux themes, `outils/contrastes.mjs`, `menu/style.css` tokenise.

Regle de theme retenue, a respecter : le theme PAR DEFAUT (`:root`, sans attribut) reproduit exactement l'apparence actuelle du jeu, qui est sombre. `[data-theme="clair"]` fournit la contrepartie claire. Aucun bloc `prefers-color-scheme` en phase 2 : les captures Playwright tournent en preference claire, un basculement automatique rendrait le filet de securite non deterministe. La bascule est explicite, par attribut sur `<html>`.
</objective>

Pour eviter la triple duplication, definir les valeurs sombres dans `:root`, et n'ecrire dans `[data-theme="sombre"]` que ce qui doit etre re-affirme apres un passage en clair (en pratique : les memes tokens, ecrits une fois de plus). Documenter le choix en commentaire.

<task type="auto">
  <name>Tache 2 : Le controle de contraste</name>
  <files>ui-app/outils/contrastes.mjs, ui-app/package.json</files>
  <action>
Installer `culori@4.0.2` en dependance de developpement de `ui-app`, puis ecrire `ui-app/outils/contrastes.mjs`.

Comportement :
1. Lit `styles/tokens.css`.
2. Lit la liste des paires depuis les lignes `paire: A / B seuil: N libelle` du commentaire structure. La liste des paires n'est PAS codee dans le script : sinon le design system et son controle divergent.
3. Pour chaque theme (`:root` puis `[data-theme="clair"]`), resout la valeur de chaque token dans le bloc du theme, avec repli sur `:root` si le theme ne le redefinit pas.
4. Calcule le ratio avec `wcagContrast` de `culori`. Ne jamais recoder la formule : les seuils de linearisation sRGB sont un piege classique.
5. Affiche une ligne par paire et par theme, en francais, et sort en 1 des qu'une paire est sous son seuil, avec le message : les seuils ne se negocient pas, ce sont les tokens qui bougent.

Ajouter le script npm `"contrastes": "node outils/contrastes.mjs"` (une seule commande).

Faire passer le controle au vert. Si une paire echoue avec les valeurs actuelles du jeu, corriger la VALEUR DU TOKEN, jamais le seuil, puis relancer `npm run captures` : la correction fait peut-etre bouger un ecran ancien, auquel cas passer par `npm run captures:comparer` puis `npm run captures:valider` et consigner le changement dans le SUMMARY (c'est une amelioration d'accessibilite voulue, ACC-02).

Ajouter aussi un test negatif : abaisser temporairement un token pour qu'une paire tombe sous le seuil, verifier la sortie en 1 et le message, puis retablir.
