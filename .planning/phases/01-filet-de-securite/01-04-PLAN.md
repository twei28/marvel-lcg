  <action>
Le serveur ignore complètement les query strings sur les `.html` (mesuré : `/main.html?ui=old` renvoie les mêmes octets) : la bascule est donc **100 % côté client**, zéro modification backend. Et la query string est PERDUE au lancement d'une partie (`js/prepare/launcher.js` fait `window.location.href = "/?hot_seat"`) : la préférence doit donc survivre à une navigation ⇒ `localStorage`, jamais un cookie (le serveur pose déjà `session_token` et `app_version`, on ne s'en approche pas).

Créer `public/js/ui-switch.js`, script classique (pas de module), configuré par data-attributs sur sa propre balise :
```html
<script src="/public/js/ui-switch.js" data-role="nouvelle" data-ancienne="/scene.html" data-nouvelle="/prepare.html" defer></script>
```
Comportement :
- Clé de préférence : `localStorage.getItem('ui')` ∈ `'old' | 'new' | null`. Tous les accès à `localStorage` sont dans un `try/catch` (mode privé).
- `data-role="ancienne"` : n'affiche le bandeau QUE si la préférence vaut `'old'`. Bandeau collé en haut de page, texte français sans jargon : « **Vous utilisez l'ancienne version.** » + bouton « Revenir à la nouvelle version ». Le bouton écrit `ui=new` puis `location.href = data-nouvelle`. Le bandeau ne doit pas recouvrir le contenu (pousser le body, ou `position: sticky`), et ne doit s'afficher qu'après le rendu (`defer`).
  **Point critique** : si la préférence est vide ou `'new'`, la page doit rester STRICTEMENT identique à aujourd'hui — sinon les références de captures de `scene.html` changent pour rien.
- `data-role="nouvelle"` : ajoute un lien discret en bas de page « Revenir à l'ancienne version », qui écrit `ui=old` puis `location.href = data-ancienne`. Même exigence : rien d'autre ne bouge visuellement... sauf ce lien, qui EST un changement visuel volontaire sur `prepare.html` et devra donc passer par la page de comparaison et un `npm run captures:valider` (tâche 2).
- Commenter en tête du fichier la convention pour les pages migrées ensuite : quand l'ancienne version n'existe plus sous son propre nom (cas de `marvel.html` en phase 5), on en dépose une copie VERBATIM dans `public/legacy/<page>.html`, qu'on ne retouche plus jamais, et `data-ancienne` pointe dessus.
  </action>

# attendu : 200 application/javascript

**A. `prepare.html`** — insérer l'aiguillage en TOUT PREMIER élément du `<head>`, avant tout CSS et tout autre script (sinon flash de la nouvelle UI avant redirection) :
```html
<script>
(function () {
  var q = new URLSearchParams(location.search);
  var choix = q.get('ui');
  if (choix === 'old' || choix === 'new') {
    try { localStorage.setItem('ui', choix); } catch (e) {}
  } else {
    try { choix = localStorage.getItem('ui'); } catch (e) { choix = null; }
  }
  if (choix === 'old') { location.replace('/scene.html' + location.hash); }
})();
</script>
```
Puis, en fin de `<body>`, la balise `ui-switch.js` avec `data-role="nouvelle"`.

**B. `scene.html`** — ajouter uniquement la balise `ui-switch.js` avec `data-role="ancienne"`, `data-nouvelle="/prepare.html"`. Ne rien modifier d'autre dans ce fichier de ~2000 lignes.

**C. `ui-check/tests/bascule.spec.ts`** — quatre vérifications, projet `pc` uniquement, chacune dans un contexte navigateur neuf (`test.use({ storageState: undefined })` ou `browser.newContext()`) pour partir d'un `localStorage` vide :
1. Sans préférence : `goto('/prepare.html')` → l'URL finale reste `/prepare.html`.
2. Point d'entrée : `goto('/prepare.html?ui=old')` → l'URL finale est `/scene.html`, et le bandeau « Vous utilisez l'ancienne version » est visible.
3. Mémorisation : dans le même contexte, `goto('/prepare.html')` (sans paramètre) → on arrive encore sur `/scene.html`. C'est le cas qui compte : la query string est perdue au lancement d'une partie.
4. Retour : cliquer « Revenir à la nouvelle version » → URL `/prepare.html`, puis `reload()` → toujours `/prepare.html` (la préférence a bien été remise à `new`).

Lancer `npm run captures:comparer`, puis `npm run captures:valider` et répondre `OUI` pour figer la nouvelle référence de cet écran uniquement. C'est le premier usage réel de la boucle de validation.
